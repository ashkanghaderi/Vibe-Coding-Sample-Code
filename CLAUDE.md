# Flashcards — working notes for Claude Code

This file is the subject of Chapter 3. It is also load-bearing: the sessions in
this book were run against exactly this file, so if you change it, you are no
longer reproducing the book.

## What this is

A flashcards app with AI-assisted card generation, built twice — once in SwiftUI
for iOS, once in Compose for Android — from the same specification.

## Project shape

```
ios/          SwiftUI app. Project generated by XcodeGen from project.yml.
android/      Compose app.
scripts/      Build, run, and screenshot. CI runs these; so should you.
screenshots/  Written by the scripts. Never edited by hand.
```

## Rules that matter

**Never commit `Flashcards.xcodeproj`.** It is generated from `ios/project.yml`.
Edit the YAML, not the project. A generated file in version control is a merge
conflict waiting to happen and a thing neither of us can review.

**Simulator builds are unsigned.** Pass
`CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO`. Without it the build fails
with *"resource fork, Finder information, or similar detritus not allowed"* —
which looks like a code problem and is not. See Chapter 6.

**Screenshots come from `scripts/shoot-ios.sh`.** Never take one by hand. A
screenshot that was not produced by the script cannot be trusted to match the
code beside it.

**No API keys in this repository, ever.** The AI card generator reads
`FLASHCARDS_API_KEY` from the environment. There is a `.env.example`; there is
no `.env`.

## Verifying a change

```bash
./scripts/shoot-ios.sh     # builds, runs, and re-captures
```

If that fails, the change is not done. "It compiles" is not the bar here —
the bar is that the app still launches and still looks right.
